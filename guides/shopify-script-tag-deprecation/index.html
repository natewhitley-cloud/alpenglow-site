Shopify script tags stop working March 1, 2027: which apps on your store will break

Updated October 26, 2026

Short answer: on March 1, 2027 Shopify stops loading script tags on storefront pages. Script tags are an older way for apps to add JavaScript to your store without touching your theme. Any app on your store that still relies on one stops working on your storefront that day, unless its developer has moved it to an app embed or a web pixel. You can't see or remove script tags in your admin, so the fix is up to each app's developer. Your job is to find out which apps are affected and ask.

The dates

DateWhat changes
August 26, 2026Script tags stopped running on the order status page (earlier for Plus stores).
October 1, 2026Apps can no longer create or update script tags. Existing ones keep running on storefronts for now.
March 1, 2027Shopify stops loading script tags on storefront pages. Whatever an app loaded that way stops appearing.

Shopify asked app developers to release replacements before October 1, 2026. Not every app may have done it, and Shopify isn't planning to warn merchants: its developer documentation says an earlier plan for a warning banner was dropped.

How to check which apps on your store still use script tags

  1. Open your storefront's page source. Visit your store's homepage in a desktop browser, then choose View page source (in Chrome, press Ctrl+U on Windows or Cmd+Option+U on a Mac). Use the page source, not the developer tools, so you see what Shopify sent before any script ran.
  2. Search for asyncLoad. Press Ctrl+F or Cmd+F and search for asyncLoad. Shopify prints your store's storefront script tags in a short block of code there, as a list that starts with var urls = [. If the search finds nothing, your storefront isn't loading any script tags.
  3. Read the list of web addresses. Each address in that list is one script tag. The slashes appear as \/, so https:\/\/example.com\/widget.js means https://example.com/widget.js. Many end with ?shop=yourstore.myshopify.com.
  4. Match each address to an app. The domain usually names the app or its developer. If it doesn't, search the web for the domain. Some apps host their files on Shopify's own servers (cdn.shopify.com), which doesn't name the app; the file name sometimes does.
  5. Check each app against Settings → Apps. Script tags only exist for apps that are still installed, because Shopify removes an app's script tags when you uninstall it. So every address in the list belongs to an app you still have.

What to do about each app

What you findWhat to do
An app you still useAsk the developer: "Has your app moved off script tags to an app embed or a web pixel, and do I need to do anything?" If they say it now uses an app embed, open your theme with Edit theme, go to App embeds and check that it's switched on for your published theme. App embeds are switched on per theme, so a theme you publish later needs the same check.
An app you don't use any moreUninstall it. Shopify removes its script tags for you. Then check your theme for code the app may have written into your theme files, which uninstalling doesn't remove.
A custom app built for your storeAsk whoever built it. Custom apps that can't use app extensions may need the script moved into your theme, for example with a Custom Liquid section.
An address you can't placeSearch the web for the domain. If it isn't from any app you recognize, treat it as a security question: review your installed apps and your staff and collaborator accounts.

After a developer moves their app, its address should disappear from the asyncLoad list. If an app shows up twice on a page, for example two copies of the same widget, the old script tag and its replacement may both be running. Tell the developer, because that can also double-count analytics.

What happens if you do nothing

On March 1, 2027 the script stops loading, and whatever it did on your storefront goes away without an error: a review widget, a popup, a chat button, a tracking script. Nothing in your admin will flag it, so the first sign may be a customer or a drop in a report. Leftover script tag records do nothing after that date, so there is nothing to clean up. The only work is moving the apps you still need.

Common questions

Can I see or delete script tags in my Shopify admin?

No. Script tags belong to the app that created them and don't appear in your admin or your theme code. You can see their web addresses in your storefront's page source, but only the app's developer can change or remove them. When you uninstall an app, Shopify removes its script tags for you.

Will Shopify warn me about apps that still use script tags?

Don't count on it. Shopify's developer documentation says an earlier plan to show merchants a warning banner was dropped for now, and it doesn't describe any other merchant notice. Check your store yourself and ask the developers of the apps you find.

Does the script tag change affect my checkout or order status page?

The order status page went first: script tags stopped running there on August 26, 2026, and earlier for Plus stores. The March 1, 2027 date is for storefront pages, such as your home, product, collection and cart pages.

What about analytics and tracking scripts?

Shopify's recommended replacement for scripts that only collect analytics or conversion data is a web pixel. Web pixels don't need switching on in the theme editor; you approve the app's access when you install or update it. If a tracking app on your store still uses a script tag, ask its developer whether it has moved to a web pixel.

Do I need to clean up leftover script tags after March 1, 2027?

No. Shopify's documentation says leftover script tag records have no effect after storefronts stop loading them, so there is nothing to delete. The work is making sure the apps you still use have moved to an app embed or a web pixel before then.
